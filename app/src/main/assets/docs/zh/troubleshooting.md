# 故障排查

某件事没有按应有的方式工作。本页收集了实际出现过的故障，每个都附带背后的原因和该改
什么。

有三份同级的文档，值得先弄清你要哪一份：

- **本页**回答“它坏了”——模型加载不了、运行停了、触发器从未触发。
- [`faq.md`](faq.md) 回答“能不能、会不会、在哪里”——某件事到底是否受支持，以及在哪里
  找到它。
- [`user-guide.md`](user-guide.md) 说明每个界面和功能如何工作，是行为的权威描述。另外
  两份都链接到它，而不是重复它。

用户指南以及从这里链接到的其它文档，除「常见问题」外，都在浏览器中打开且为英文；引用
其章节时使用原文标题。

## 模型加载失败：“out of memory”

本地 LLM 需要一大块连续内存。如果加载模型失败：

- 打开**模型**并点一个更小模型上的**启用**。4-bit 量化的变体往往能装进全精度模型装不
  进的地方。
- 如果设备上有多个模型，之前激活的那个会一直保持加载，直到新的被激活。来回切换几次
  会让设备内存碎片化——彻底关闭应用（从最近任务列表把它滑掉）再打开，能可靠地释放原
  生句柄。
- 确保没有其他重应用在后台运行。

<!-- en: inference-is-very-slow -->
## 推理非常慢

没有可用的 GPU 时，本地模型只在 CPU 上运行，明显更慢（尤其是最初几个 token）：

- 回复正在写的时候，智能体状态会显示模型实际运行在哪个后端。如果显示了 CPU 而选中的
  是 **GPU**，说明 GPU 启动失败，本次会话发生了回落。
- **设置 → 模型**里的**测试后端**会测量所选后端生成的速度。
- 从**模型**界面换一个更小的模型——即使是 1B-2B 参数的模型，在 CPU 上也可能比 7B+ 的快
  得多。
- 在**设置 → 生成 → 高级**里调低**最大上下文长度**。上下文越短，每个 token 的工作越少。

<!-- en: the-app-freezes-while-the-model-is-answering -->
## 模型回答时应用卡死

在某些手机上，本地模型在 **GPU** 上处理回复时屏幕会失去响应，Android 可能提议关闭应
用。模型和屏幕共用一个图形芯片，模型可能把它占得太久，屏幕只能等待。设备端引擎有一个
旨在保持屏幕流畅的低优先级模式，但应用还无法开启它
（[LiteRT-LM#3992](https://github.com/google-ai-edge/LiteRT-LM/issues/3992)）。

在那之前，打开**设置 → 模型**，把**推理后端**设为 **CPU**，再点横幅上的**重启**。回复会
变慢，但屏幕不再等模型。

<!-- en: a-tool-says-it-is-unavailable -->
## 工具提示不可用

两个常见原因：

- 一个委派给云端服务商的内置工具（例如 **delegate_task**）需要**设置 → 模型 → 外部服
  务商**里至少有一个云端 API 密钥。没有密钥时，它不会出现在智能体面前。
- MCP 服务器工具要求服务器本身可达。打开**工具**界面，确认服务器仍列在 **MCP 服务器**
  下；如果 URL 变了或服务器宕机，该工具会在控制台以错误事件失败。

<!-- en: an-mcp-server-is-connected-but-a-tool-i-expect-isnt-there -->
## MCP 服务器已连接，但预期的工具不在

如果服务器行显示 `ok` 而工具仍始终不出现，那很可能是服务器没有把它发布给本应用。有些
工具只在支持额外特性的客户端上工作，而 Knotwork 还没有这些特性，行为良好的服务器会
把这些工具从列表中略去，而不是提供一个会失败的东西。见
[服务器行上的工具数量意味着什么](user-guide.md#what-the-tool-count-on-a-server-row-means)——这是
真实的限制，不是你能从工具界面修好的配置错误。

如果工具列在该服务器下但标为*未向智能体提供*，那说明另一个工具同名了——设备上的一个
工具，或上方列出的某个服务器上的同名工具。见
[两个工具同名时](user-guide.md#when-two-tools-share-a-name)。

<!-- en: the-same-question-goes-to-the-cloud-one-time-and-stays-local-the-next -->
## 同一个问题有时走云端，有时留在本地

这通常是路由器在读对话，不是 bug。若想让决定可复现，见
[为什么同一个问题可能走不同的路](user-guide.md#why-the-same-question-can-take-a-different-route)。

<!-- en: a-background-run-dies-the-moment-i-leave-the-app -->
## 一离开应用后台运行就中断

几乎总是电池限制而不是应用本身：用默认设置时，系统可以在应用离开后几秒内回收进程。
见
[电池设置决定这些功能是否会发生](user-guide.md#battery-settings-decide-whether-any-of-this-happens)。
大多数从未产生结果的触发器和计划任务背后也是同一个原因。

<!-- en: a-pipeline-went-missing -->
## 流程不见了

如果你删除或重命名了某个聊天绑定的流程，该聊天在下一条消息时会回退到库中标记为
**默认**的流程。不存在损坏状态——回复照常工作——但这段对话会开始使用当前被标为默认的
那个流程。要重新给聊天选一个流程，重新打开**流程**界面并使用**设为默认**，或者新建一
个聊天来重新绑定。

<!-- en: the-agent-stopped-mid-run -->
## 智能体在运行中途停止

一次长运行可能触及某个**运行上限**。它会暂停并询问：聊天里会显示
**因达到安全限制而暂停**，写明哪项额度用完、用了多少，并给出**继续（+N）**或
**停止运行**。继续会让它再获得同一额度的一份，并从上次停下的地方接上；用完时它会再次
询问。

如果运行是结束而不是暂停，聊天会显示**因达到安全限制而停止**——你选择了停止、等待窗
口在你回答前关闭，或者运行没有可等待的记录（从编辑器发起的测试运行）。那条消息上的
**调整限制**会打开可以调高下次上限的界面。

在调高任何东西之前，有两件事值得知道。涉及的上限可能是 **token** 那项而不是步数那项，
所以读消息，别想当然；而不由你启动的运行受**后台**上限约束，它们在同一界面单独设置。

但要先读消息，因为并非每次中途停止都是上限。**已停止：运行毫无进展**表示运行在自我重
复，因此被结束——调高上限只会让它多绕几圈，所以打开控制台，看看是哪个步骤不断回来。
**已停止：运行无响应**又是第三种情况：某个步骤停止响应，通常是一个从未应答的工具或服务
器，运行被结束，好让其他消息能跑。那个很可能重试一次就好了。

<!-- en: a-trigger-didnt-fire -->
## 触发器没有触发

打开触发器，读它的**评估日志**（见
[触发器](user-guide.md#checking-what-a-trigger-has-been-doing)）——答案几乎总在那里，而它呈现三
种形态中的哪一种，决定接下来做什么：

- **你预期的那一刻有一条记录，说它没有运行。** 原因会写明：条件未满足、该时间窗口内
  已触发过、触发器已关闭，或没有绑定流程。没有东西坏掉——要么条件不是你想的那样，要
  么触发器需要绑定或启用。
- **有记录，而且它触发了但结局很糟。** *失败*指向流程（在触发器的聊天里打开那次运行，
  读控制台）。有两种失败会自我说明：*运行毫无进展*表示它在自我重复，控制台的日志会显
  示同一步骤一遍又一遍地跑，直到结束它的那一行；*运行无响应*表示某个步骤停止响应——
  控制台的日志停在它开始却从未完成的那个步骤上，那个步骤就是要看的东西，虽然
  **变量**标签页里不会有它的任何内容，因为它从未产出任何东西；*已被系统终止*表示进程在
  运行中途被杀，这是电池 / 内存压力问题，不是流程问题；*等待批准超时*表示运行停在某个敏
  感工具上，批准窗口在你回答前就过期了——要么更快回复，要么调大
  **设置 → 后台与触发器 → 审批时间窗口**，要么换一个工具不需要批准的流程。如果记录说
  *请求未能送达给你*，那是相反的情况：批准根本无法交付，所以没有通知可等。
- **那段时间前后完全没有记录**，而且列表显示**已逾期**。应用从未被唤醒去检查。这是平
  台侧的问题：把应用排除出电池优化，而在带有厂商额外层（三星、小米、一加等）的手机上，
  还要把它从任何“休眠”/“深度休眠”应用中移出。注意每个非充电触发器都跑在可延迟的后台
  计划上（见 [触发器多久后触发](user-guide.md#how-soon-a-trigger-fires)）——检查来晚了是正常
  的；晚到触发器自身节奏许多倍就不正常。

一个从未被评估过的触发器会显示*“暂无评估记录”*——在你刚创建它之后这是正常的，因为第
一次检查要等下一次轮询。

## 记忆搜索找不到明显存在的条目

如果一个你明明知道存在的记忆从未出现在回复里（或记忆界面的搜索里），按这个清单往下
查：

- **节点没有在读记忆。** 只有带**长期记忆**输入标志的节点才会从存储中拉取。打开流程，
  检查节点的*输入数据*分区，并观察**控制台 → 记忆**筛选：如果这次运行没有
  `Memory: query=… → N hits` 这一行，说明活动节点从未查询过记忆。
- **相似度阈值太高。** 较高的**设置 → 记忆 → 相似度阈值**会在弱相关的分块到达提示词之前
  把它们丢掉。调低它（或者置顶该条目——置顶分块完全绕过阈值，并且总是排在最前）。
- **更新的条目抢到了位置。** 年龄从不会让条目失去资格——通过相似度阈值的分块无论多旧都
  仍然可检索——但新鲜度是并列时的排序依据，因此当通过阈值的条目多于
  **搜索结果数（Top-K）**允许的数量时，较新的会赢得这些位置。调高 top-K、调高
  **时效半衰期**（它会拓宽新鲜度仍有较大权重的窗口），或者置顶该条目。
- **另一个条目说了同样的事。** 含义与排名更高者接近的条目会被折叠进去，这样换个说法的
  重复项就不会占用第二个位置。保留下来的是置顶的那一个（如果有），否则是排名最高的
  ——而在相关度和年龄大致相同时，你手动保存的条目排在提取出来的条目之前。使用设备端嵌
  入模型时，这还会误伤用俄语写成的不相关条目，模型分不清它们——见
  [已知限制](faq.md#known-limitations)。
- **条目在等待重新嵌入。** 在另一个嵌入服务商下导入的分块，要等后台重新嵌入完成才能被
  匹配（期间它的得分约为 0）。等一会儿，或者用**设置 → 记忆 → 重新生成向量**强制进行。
- **服务商变了。** 换掉**嵌入模型**会让现有分块留在旧的向量空间里；运行**重新生成向量**，
  让整个存储重新共享当前服务商的空间。这种不一致持续期间，记忆卡片会显示一条常驻的
  *建议重新生成向量*横幅。
- **“禁止本地模型访问网络”开着。** 开着它时，记忆不能把 OpenAI 当作**嵌入模型**，也不能
  使用地址不是 `localhost` 或私有 IP 的 Ollama，并会回落到设备端模型——因此在关掉该限制
  之前，由另一个服务商嵌入的条目得分约为 0。同一条限制也不会提供内置的 `search_tool`，
  所以某一步若在 Wikipedia 查事实，会报告一个点名该设置的拒绝，而不是返回摘要。
- **它从未被提取过。** 自动提取只保留持久事实（偏好、事件、关系），跳过闲聊和你已经拥
  有的事实。已有事实的变化会更新该条目，而不是新增一条——如果那是置顶条目，则会在一旁
  等待。如果某个事实没被收进去，用**保存到记忆**或**添加记忆**悬浮按钮手动添加。

## 启动时出现“无法解锁你的数据”

所有本地数据都存放在一个加密数据库中，其密钥位于 Android 的硬件 keystore 中。在少数
情况下——通常是 OS 更新之后，或者因为 keystore 的瞬时故障——该密钥会暂时无法读取，应用
会显示一个专门的恢复界面，而不是启动：

- **先点重试——可能需要不止一次。** keystore 故障往往是暂时的；如果密钥重新可读，应用会
  打开你现有的数据，分毫未动。在再次重试之前重启设备，在某些情况下有帮助。
- **清除数据是最后的手段。** 如果重试始终无法越过这个界面，密钥就永久丢失了，加密数据库
  再也没人能打开——包括应用自己。**清除数据**会删除数据库、你的智能体工作区文件、附件和
  计划任务，并生成新密钥，让你可以重新开始。设置和已保存的密钥会保留，已下载的模型也会
  保留——它们会重新列在模型下，处于未启用状态，所以在聊天前先选一个。此操作不可逆，并
  有输入文字确认把关。

在这种状态下，应用绝不会自动删除或重新加密你的数据：没有原始密钥，数据库内容无法恢
复，因此要不要清空始终由你决定。

<!-- en: installing-over-a-copy-from-google-play-fails -->
## 覆盖安装 Google Play 版本失败

在已经从 Google Play 装过它的设备上，安装 GitHub 的发布版 APK，或 F-Droid 的 Knotwork，
会以“应用未安装”或“软件包与现有软件包冲突”之类的错误停下；具体措辞取决于 Android 版本
和执行安装的应用。反过来也一样：从发布版 APK 或 F-Droid 安装的副本，无法从 Google Play
更新。

两个文件都没有坏。Google Play 用与 GitHub 发布版和 F-Droid 不同的密钥给应用签名
（[各渠道的签名身份](release.md#signing-identities-by-channel)），而 Android 只会用同一签
名者的副本来更新应用。要切换渠道：

1. 做备份：设置 → 隐私 → **备份与恢复** → **备份…**——[做法](user-guide.md#backup--restore)。
   勾选**包含 API 密钥与登录信息**，把密钥一并带上，并把文件存到卸载碰不到的地方——下载
   文件夹、存储卡或云端硬盘。
2. 卸载应用。这会删掉它在设备上保存的一切，包括已下载的模型。
3. 从另一个渠道安装，打开**备份与恢复** → **从文件恢复…**，选择备份文件，输入它的密码并
   确认。应用重启后，从它显示的列表里重新下载模型。

你安装的版本必须能读取该备份。来自更新发布版的备份可以恢复，除非那个发布版改动了备份
格式或数据库；那时恢复会被拒绝，并要求你先更新。Google Play 在更新审核期间可能落后于
Releases 页面，F-Droid 则要等下一次构建跑完才跟上，所以在卸载之前，先确认另一个渠道提
供的是同一个发布版或更新的版本。

<!-- en: a-model-download-paused-after-five-hours -->
## 模型下载在五小时后暂停

Android 允许应用每天在后台传输数据六小时；如果一次传输超过这个时间，就会停止应用。因
此模型下载在下载五小时后会自行暂停。它会发一条通知说已暂停（如果应用获准发通知），而
模型界面会在你下次打开、且没有其他下载在进行时这样提示，并给出**继续**按钮——或者初始
设置的下载步骤，或“发现”中该模型的页面，如果你先到达其中某一个。不会丢东西：重新启动
同一个下载，它会从停下的地方继续。

<!-- en: a-downloaded-model-did-not-match-its-checksum -->
## 下载的模型校验和不匹配

Hugging Face 会为它托管的模型文件发布 SHA-256，应用在安装模型前会把下载的文件与它比较。
两者不同时，文件会被删除，不会安装模型，应用会以与下载暂停相同的方式提示。

有一种发生方式：文件在你下载中断期间于 Hugging Face 上变了，所以中断前取到的部分和之
后取到的部分属于该文件的两个版本。重新开始下载——它会从头获取当前版本。

如果全新下载仍以同样方式失败，那么到达你手机的文件就不是 Hugging Face 发布的那一个。
换一个网络试试；如果仍然发生，就提一个 issue，写明模型和文件。
